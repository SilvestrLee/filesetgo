# 8. Preset Schema

Define a typed preset contract.

A preset should contain enough information to support:

- stable identity;
- revision/version;
- category;
- user-facing name;
- concise description;
- intended use;
- requirement values;
- provenance;
- future source freshness.

Conceptually:

type FileSetGoPreset = {
    id: string;
    revision: number;

    category: string;

    title: string;
    description: string;

    requirements: {
        targetBytes?: number;
        maxWidth?: number;
        maxHeight?: number;
        outputFormat: 'jpeg' | 'png' | 'webp';
        dimensionPolicy: 'hard' | 'flexible';
    };

    provenance: {
        kind: 'filesetgo-recommended' | 'external';
        sourceUrl?: string;
        verifiedAt?: string;
        reviewAfter?: string;
    };
};

This shape is illustrative.

Improve it where necessary, but preserve the architectural concepts.

Do not store executable callbacks inside preset definitions.

Presets should primarily be deterministic data.

# 13. Preset Validation

Create deterministic preset validation.

Reject or fail development validation for:

- empty ID;
- duplicate ID;
- revision < 1;
- unsupported output format;
- HEIC as output;
- invalid targetBytes;
- invalid/zero dimensions;
- dimensions exceeding governed core safety where relevant;
- invalid dimensionPolicy;
- missing title;
- missing description;
- invalid provenance combinations.

For external provenance require, at minimum:

- sourceUrl;
- verifiedAt.

Even though no external presets ship in this sprint, the contract should
prevent unsourced future platform claims.

Do not silently accept malformed catalog data.

# 17. Shared File Selection

Do NOT create two unrelated upload/select workflows.

Quick Fit and Guided Fit should share the currently selected source file.

A user should be able to:

1. choose a file;
2. switch between Quick Fit and Guided Fit;
3. retain the same selected file.

Switching modes must not:

- re-preflight unnecessarily;
- create a second source Blob;
- lose the selected file;
- trigger processing.

Preflight remains once per newly selected file.

# 26. Mode Switching

Switching modes should behave predictably.

Quick Fit → Guided Fit:

- retain selected file;
- do not process;
- show prior preset selection if still valid, otherwise no preset selected.

Guided Fit → Quick Fit:

- retain file;
- preserve existing manual Quick Fit values unless the user explicitly
  chose "Adjust settings" from a preset.

"Adjust settings" is an intentional overwrite/prefill action.

A normal mode toggle should not silently destroy the user's manual values.

# 30. Unreachable Preset Result

If the selected preset cannot be met within FSG-002 guardrails, keep
`unreachable` distinct from failure.

User-facing guidance may say:

"We couldn't reach this recommendation without going beyond FileSetGo's
quality or size guardrails."

Offer:

Adjust settings

which sends the preset into Quick Fit so the user can loosen:

- target size;
- dimensions;
- format.

Do not silently weaken the preset and claim it was met.

# 31. Already-Ready Evaluation

Add a lightweight deterministic evaluator that can identify when the
source already satisfies a preset without processing.

This is allowed only when all required facts are known from preflight.

For these initial presets, a source is already ready only if:

- source format already equals preset output format;
- source bytes <= preset targetBytes;
- source width <= preset maxWidth;
- source height <= preset maxHeight.

If all are true:

show:

"This file already fits this recommendation."

Do not re-encode by default.

Offer:

Use this file

and:

Adjust settings

The source remains entirely local.

Do not claim "already ready" based on filename/MIME alone.

Preflight facts remain authoritative.

---

# 32. Already-Ready Download

If the original source already satisfies the selected preset:

do not manufacture a processed Blob unnecessarily.

The original `File` may be used as the local ready file.

If offering a download action, either:

- allow the original file to be used directly; or
- clearly explain that no processing was needed.

Do not rename/re-encode merely to make the workflow look active.

Preserve truthful UX.

---

# 33. Original Filename in Already-Ready Case
