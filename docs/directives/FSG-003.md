# 1. Milestone Objective

Build the first real FileSetGo user experience around the existing
browser-processing foundation.

The user-facing proposition is:

File. Set. Go.

Get your file ready for where it needs to go.

Quick Fit must allow a user to:

1. choose an image;
2. see what FileSetGo detected;
3. enter the requirement the file needs to meet;
4. run local browser processing;
5. understand the result;
6. download the ready file;
7. start again without reloading the application.

No account is required.

No source image is uploaded to FileSetGo.

---

# 2. Product Principle

- binary search;

- WASM;

"My website says this file must be under 200 KB."

or:

"I need this image no wider than 1200 px."

FileSetGo should translate those requirements into the existing core API.

# 15. Output Format

Offer:

- Keep original
- JPEG
- PNG
- WebP

Rules:

JPEG source:
"Keep original" → JPEG

PNG source:
"Keep original" → PNG

WebP source:
"Keep original" → WebP

HEIC source:
HEIC output is unsupported.

Therefore "Keep original" must not result in HEIC output.

For HEIC input, automatically resolve the initial output-format choice to
WebP and clearly show that the ready file will be WebP.

Do not add HEIC output merely for UI symmetry.

# 16. Transparency Warning

core has actually inspected meaningful transparency.

Do not add a transparency scanner in FSG-003.

# 19. Routing Between Existing Core APIs

Quick Fit should choose the appropriate existing core capability.

If targetBytes is supplied:

use:

processImageToTarget()

If no targetBytes is supplied but the user requested:

- format conversion;
- dimension reduction;
- or both;

processImage()

Do not run the target-size optimizer when no target exists.

If the user has selected:

- no target size;
- no dimension change;
- Keep original format;

then there is no meaningful transformation.

Disable the primary action or explain:

"Add at least one requirement for your file."

Do not perform a pointless decode/re-encode.

# 27. Unreachable Outcome UX

An `unreachable` result is NOT a system error.

"Allow dimension adjustment and try again."

"That file-size limit is too small to reach within FileSetGo's quality and
dimension guardrails."

Offer options such as:

- choose a slightly larger target;
- use JPEG/WebP instead of PNG where relevant;
- allow dimension adjustment if it was disabled.

Do not display raw enum names as the primary message.

# 28. PNG Target Guidance

Do not add PNG quantization.

Do not steer users aggressively away from PNG.

# 62. Loading States

While processing:

- primary processing action disabled;
- input requirements should not silently mutate the active job;
- Cancel remains available.

# 63. Result Integrity

- returned format;
- target metadata.

# 64. Failure Recovery

A failed job must not leave the workflow unusable.

After failure, user should be able to:

- adjust requirements;
- retry;
- select another file.

Do not require reload.

Keep the validated source available after an ordinary processing failure
unless the source itself was invalid.

---

# 65. Cancel Recovery

After cancellation:

- no stale result;
- controls return to usable state;
- source file remains available;
- user may adjust requirements and run again.

Cancel should not behave like full reset.

Reset and Cancel are different actions.

Use concise, human language.

Prefer:

"Your file is ready."

over:

"Processing operation completed successfully."

Prefer:

"We couldn't get it under 50 KB without making it smaller."

over:

"TARGET_UNREACHABLE_HARD_DIMENSIONS."

Avoid overexplaining.

FileSetGo exists partly because many users do not know file-management
terminology.

---

# 67. Public Trust

The shell should clearly communicate three things without overwhelming the
user:

1. what FileSetGo does;
2. what the user needs to provide;
3. that the image is processed locally.

Trust should come from clarity, not security-themed marketing badges.

Do not claim:

"100% secure"
"unhackable"
"military-grade"

# 68. FSG-003 Acceptance Criteria

FSG-003 may close only when:

1. `/` is a real FileSetGo public shell.
2. Quick Fit is immediately discoverable.
3. User can select/drop JPEG, PNG, WebP and HEIC.
4. Preflight rejection is translated into useful UI.
5. Source format/dimensions/size are shown.
6. Target file size can be entered in KB/MB.
7. Optional max dimensions can be entered.
8. Output format can be selected.
9. HEIC cannot be selected as output.
10. FLEXIBLE/HARD behavior is exposed in plain language.
11. Target-size jobs use `processImageToTarget()`.
12. Resize/format-only jobs use `processImage()`.
13. No-op jobs are prevented.
14. Processing can be cancelled.
15. Successful result shows real output metadata.
16. Successful output can be downloaded locally.
17. Blob URLs are cleaned up.
18. Unreachable outcomes are distinct from runtime errors.
19. Reset/start-again works without reload.
20. Replacement files cannot receive stale results.
21. UI is keyboard usable.
22. UI is mobile responsive.
23. Privacy language is accurate.
24. No upload/conversion server endpoint exists.
25. HEIC remains lazy-loaded.
26. Existing 202 core tests remain green.
27. New UI/workflow tests pass.
28. Laravel feature tests pass.
29. No FSG-004 preset/guided workflow functionality has begun.
30. No manual project-owner QA is required for closure under ADR-013.

If any genuine criterion remains missing, keep FSG-003 open.
